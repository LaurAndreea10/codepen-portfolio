Every particle is moved by a compute shader written in WGSL, and rendering reads the same buffer directly, with no data passing through JavaScript. Without WebGPU, the same physics runs on the CPU, on Canvas 2D, with fewer particles.

Cum funcționeazăHow it works

1 · Un buffer pe GPU1 · One buffer on the GPU

Pozițiile și vitezele stau într-un singur storage buffer (16 octeți pe particulă). JavaScript îl umple o dată, la pornire, și apoi nu-l mai atinge.Positions and velocities live in one storage buffer (16 bytes per particle). JavaScript fills it once, at start, and never touches it again.

2 · Compute shader2 · Compute shader

La fiecare cadru, 64 de fire pe grup actualizează câte o particulă: forța spre atractor, frecare, ieșire pe o margine și intrare pe cealaltă.Each frame, 64 threads per workgroup update one particle each: force towards the attractor, damping, wrap-around at the edges.

@compute @workgroup_size(64)
fn step(@builtin(global_invocation_id) id: vec3u) {
  var p = ps[id.x];
  p.vel = p.vel * damping + force(p) * u.dt;
  p.pos = wrap(p.pos + p.vel * u.dt);
  ps[id.x] = p;
}

3 · Desenare instanțiată3 · Instanced drawing

Vertex shaderul citește același buffer și desenează un pătrățel pentru fiecare particulă, colorat după viteză, cu amestec aditiv. Datele nu se întorc niciodată în JavaScript.The vertex shader reads the same buffer and draws a small quad per particle, coloured by speed, with additive blending. The data never comes back to JavaScript.

4 · Fallback onest4 · An honest fallback

Dacă navigator.gpu lipsește sau nu dă un adaptor, aceeași fizică rulează în JavaScript pe Canvas 2D, cu cel mult 6.000 de particule. Eticheta din colț spune mereu ce cale rulează. Forțează fallback-ul cu ?mode=canvas.If navigator.gpu is missing or returns no adapter, the same physics runs in JavaScript on Canvas 2D, with at most 6,000 particles. The corner label always says which path is running. Force the fallback with ?mode=canvas.

Ce am verificat: calea Canvas 2D și pornirea WebGPU în Chrome headless pe Linux. Nu am verificat pe GPU-uri reale de telefon, în Safari sau în Firefox; numărul de cadre pe secundă depinde mult de placa video.What I checked: the Canvas 2D path and WebGPU start-up in headless Chrome on Linux. Not checked on real phone GPUs, in Safari or in Firefox; frame rate depends heavily on the graphics card.
