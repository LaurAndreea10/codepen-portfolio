CSS random() ca generator de numere pentru WebGL

✍️ Laura Andreea📅 Noiembrie 2026⏱ 5 min lectură🇷🇴 RO · 🇬🇧 EN summary

Challenge-ul CodePen din noiembrie a fost despre funcția CSS random(). Majoritatea intrărilor o folosesc pentru ce e făcută: culori și poziții aleatorii în pagină. În DICE DRIFT 3D am încercat altceva: CSS aruncă zarurile, iar WebGL construiește lumea din ele.

Pasul 1: o proprietate care ține un număr

O variabilă CSS obișnuită ține text. Dacă scriu --r0: random(0, 1), nu primesc înapoi un număr calculat. De aceea înregistrez proprietățile cu @property și sintaxa <number>: browserul e obligat să calculeze valoarea, iar getComputedStyle îmi dă rezultatul.

@property --r0 { syntax: '<number>'; inherits: false; initial-value: 0.5; }
@supports (opacity: random(0, 1)) {
  .rng-cell { --r0: random(0, 1); /* … --r5 */ }
}

Pasul 2: un laborator ascuns

Într-un element invizibil creez opt celule .rng-cell, citesc din fiecare câte șase valori și apoi le șterg. Fiecare celulă primește valori proprii, deci obțin 48 de numere dintr-o singură „recoltă”, pe care le pun într-un tampon. Când tamponul se golește, mai recoltez o dată.

Toată aleatoriul lumii trece printr-o singură funcție, rnd(): valurile de cristale, porțile, paleta, mutatorii zarului și evenimentele Oracolului. WebGL nu știe de unde vin numerele.

Pasul 3: să nu mă mint singură

Dacă browserul nu înțelege random(), proprietățile rămân la valoarea inițială, 0,5. Așa că verific: dacă toate valorile citite sunt identice, consider că CSS-ul nu a funcționat și trec pe Math.random(). Jocul arată deschis ce sursă folosește, într-o insignă: „CSS random() · N valori” sau „fallback JS”.

Ce am învățat: când o funcție nouă are suport limitat, cel mai onest e ca interfața să spună ce cale rulează, nu doar să se degradeze în tăcere.

Pasul 4: aceeași lume pentru toată lumea

random() e, prin definiție, imprevizibil, așa că nu poate da o „provocare a zilei” comună. Pentru modul Oracolul zilei, rnd() e înlocuit cu un generator determinist (mulberry32) inițializat dintr-un hash al datei. Restul jocului rămâne neschimbat, pentru că totul trece prin aceeași funcție.

Ce n-am verificat

  • Testele automate au rulat în Chromium, deci pe calea de fallback JS, la 1280 și 390 px. Calea nativă random() (Safari 26 și mai nou) nu a fost verificată automat.
  • Telefonul fizic și cititorul de ecran rămân de confirmat.

In English: CSS random() as a random-number source for WebGL

DICE DRIFT 3D uses CSS random() as a random-number source for a WebGL world. Custom properties registered with @property and <number> syntax force the browser to compute the value, which getComputedStyle reads back from eight hidden cells (48 numbers per harvest, buffered). If every value equals the initial 0.5, the game falls back to Math.random() and says so in a badge. The Daily Oracle swaps the same rnd() function for a seeded mulberry32 generator, so everyone gets the same world that day. Automated tests ran in Chromium, on the JS fallback path; the native path (Safari 26+) is unverified.
